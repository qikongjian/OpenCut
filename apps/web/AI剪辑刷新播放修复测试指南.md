# AI剪辑刷新播放修复测试指南

## 问题描述

**修复前的问题**：
- 使用一键剪辑功能将视频片段添加到时间轴后，可以正常播放
- 页面刷新后，时间轴中的AI剪辑片段无法播放
- 但左侧媒体面板中的视频仍可正常拖拽到时间轴并播放

**根本原因**：
AI剪辑片段使用的是临时Object URL，页面刷新后这些URL失效，而媒体面板的视频使用的是从本地存储（OPFS）恢复的持久化文件。

## 修复方案

### 1. 修复AI剪辑片段的存储机制
- **文件**: `apps/web/src/stores/ai-editing-store.ts`
- **修复**: 确保时间轴元素使用媒体库中的持久化文件引用，而不是临时下载的文件

### 2. 优化媒体文件的持久化存储
- **文件**: `apps/web/src/stores/media-store.ts`
- **修复**: 保持AI剪辑添加的媒体项的ID一致性

### 3. 修复时间轴元素的文件引用机制
- **文件**: `apps/web/src/stores/timeline-store.ts`
- **修复**: 添加媒体文件引用恢复机制，在时间轴加载时重新建立文件引用

### 4. 优化项目加载顺序
- **文件**: `apps/web/src/stores/project-store.ts`
- **修复**: 确保媒体库先于时间轴加载，保证文件引用恢复正确执行

### 5. 🚀 关键修复：预览面板文件URL重建
- **文件**: `apps/web/src/components/editor/preview-panel.tsx`
- **修复**: 优先使用本地文件重新创建Object URL，确保页面刷新后视频能正常播放

### 6. 🎯 核心修复：播放头位置初始化
- **文件**: `apps/web/src/stores/timeline-store.ts` 和 `apps/web/src/stores/ai-editing-store.ts`
- **修复**: 在项目加载和AI剪辑完成后，自动设置播放头到第一个视频片段的位置

### 7. 🚨 关键修复：URL缓存机制
- **文件**: `apps/web/src/components/editor/preview-panel.tsx`
- **修复**: 实现URL缓存机制，避免重复创建blob URL导致"AbortError: The play() request was interrupted"错误

### 8. 🔧 导入修复：添加缺失的依赖
- **文件**: `apps/web/src/stores/timeline-store.ts` 和 `apps/web/src/stores/ai-editing-store.ts`
- **修复**: 添加`usePlaybackStore`导入，解决"usePlaybackStore is not defined"错误

## 测试步骤

### 步骤1：准备测试环境
1. 启动开发服务器：`npm run dev`
2. 打开浏览器访问应用
3. 创建一个新项目

### 步骤2：执行一键剪辑
1. 打开AI剪辑面板（左侧面板中的AI智能剪辑标签）
2. 点击"生成Mock数据"按钮
3. 等待剪辑计划加载完成
4. 点击"一键剪辑"按钮
5. 等待剪辑执行完成（会显示进度条）

### 步骤3：验证剪辑后播放
1. 检查时间轴中是否出现了AI剪辑的视频片段（应该有绿色边框和Bot图标）
2. 点击播放按钮，验证视频片段能否正常播放
3. 拖拽播放头到不同片段，确认都能正常播放

### 步骤4：测试页面刷新后的播放
1. **关键测试**：刷新浏览器页面（F5或Ctrl+R）
2. 等待项目重新加载完成
3. 检查时间轴中的AI剪辑片段是否仍然存在
4. **重要**：观察播放头是否自动设置到第一个视频片段的位置
5. **核心验证**：点击播放按钮，确认视频片段在刷新后仍能正常播放
6. 拖拽播放头到不同片段，确认所有片段都能正常播放

### 步骤5：对比测试（验证媒体面板正常工作）
1. 从左侧媒体面板拖拽一个视频到时间轴
2. 播放验证该视频正常工作
3. 刷新页面后再次播放，确认媒体面板的视频仍正常工作

## 预期结果

### 修复后的预期行为：
✅ AI剪辑片段在页面刷新前可以正常播放
✅ AI剪辑片段在页面刷新后仍可以正常播放
✅ 媒体面板的视频在刷新前后都可以正常播放
✅ 时间轴中的所有视频片段都能正确显示缩略图
✅ 导出功能正常工作（不会出现"No media file available"错误）

### 技术验证点：
1. **文件引用正确性**：时间轴元素的`mediaFile`和`mediaUrl`属性指向有效的本地文件
2. **存储一致性**：媒体库中的文件与时间轴元素引用的文件一致
3. **ID一致性**：AI剪辑添加的媒体项ID与时间轴元素的mediaId一致
4. **恢复机制**：页面刷新后能正确恢复媒体文件引用

## 故障排除

### 如果刷新后仍无法播放：
1. 打开浏览器开发者工具（F12）
2. 查看Console中是否有错误信息，特别关注：
   - `🔄 恢复媒体元素文件引用` - 确认恢复机制执行
   - `🎬 预览面板使用本地文件` - 确认使用本地文件创建URL
   - `✅ 视频可播放` - 确认视频加载成功
   - `❌ 视频加载失败` - 查看具体错误信息
3. 检查Network标签，确认文件请求是否成功
4. 查看Application > Storage，确认OPFS中是否有对应的媒体文件

### 调试信息解读：
- **`🔄 恢复媒体元素文件引用`**：时间轴加载时的文件引用恢复
- **`🎬 预览面板使用缓存URL`**：预览面板使用缓存的Object URL（修复后）
- **`🎬 VideoPlayer初始化`**：VideoPlayer组件初始化视频源
- **`✅ 视频可播放`**：视频成功加载并可播放
- **`❌ VideoPlayer播放失败: AbortError`**：播放被新的加载请求中断（已修复）

### 常见问题：
- **时间轴不显示视频**：检查控制台是否有"usePlaybackStore is not defined"错误（已修复）
- **媒体库为空**：检查是否正确保存了媒体项到存储
- **文件引用丢失**：检查恢复机制是否正确执行
- **ID不匹配**：检查媒体项ID与时间轴元素mediaId是否一致
- **blob URL失效**：应该看到预览面板重新创建URL的日志
- **播放中断错误**：应该看到"预览面板使用缓存URL"而不是重复创建URL

## 技术细节

### 关键修复点：
1. **AI剪辑存储**：使用`correspondingMediaItem.file`而不是临时下载的文件
2. **媒体ID保持**：`id: item.id || generateUUID()`保持ID一致性
3. **引用恢复**：`restoreMediaElementReferences`函数恢复文件引用
4. **加载顺序**：媒体库先于时间轴加载

### 数据流：
```
下载视频 → 保存到OPFS → 添加到媒体库 → 创建时间轴元素 → 引用媒体库文件
                ↓
页面刷新 → 加载媒体库 → 加载时间轴 → 恢复文件引用 → 正常播放
```
