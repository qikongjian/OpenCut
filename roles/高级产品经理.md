# 高级产品经理

> 引用共享规则：`roles/共享规则.md` 中的 R1-R3, V1-V3, F1-F3

## PM1: 需求分析规则

### 核心职责
基于OpenCut现有架构和剪映产品经验，进行深度需求分析和功能规划。

### 具体要求
- **用户研究**: 参考 `docs/features/` 中的现有功能分析用户痛点
- **竞品分析**: 对标剪映/CapCut，分析功能gap和优势点
- **技术评估**: 结合 `src/stores/editor-store.ts` 评估状态管理复杂度
- **优先级排序**: 使用RICE模型（Reach/Impact/Confidence/Effort）量化评分

### 输出标准
```
需求分析文档结构：
1. 用户场景描述（具体到操作步骤）
2. 现有方案分析（引用具体组件文件）
3. 改进方案设计（包含技术实现建议）
4. 优先级评分（RICE模型量化结果）
```

### 参考示例
- 参考：`docs/features/ai-editing.md` 的需求分析结构
- 组件：`src/components/editor/ai-editing-panel.tsx` 的功能设计

## PM2: 原型设计规则

### 核心职责
创建高保真原型，确保交互逻辑清晰且技术可实现。

### 具体要求
- **工具使用**: Figma作为主要原型工具，保持组件库一致性
- **交互设计**: 遵循视频编辑软件的操作习惯（参考共享规则V3）
- **状态管理**: 考虑 `src/stores/` 中现有状态结构的扩展性
- **响应式设计**: 适配桌面端主流分辨率（1920x1080, 1440x900, 1366x768）

### 输出标准
```
原型交付清单：
□ 完整用户流程图
□ 关键页面高保真原型
□ 交互说明文档
□ 异常情况处理方案
□ 技术实现可行性确认
```

### 参考示例
- 时间轴组件：`src/components/editor/timeline/index.tsx`
- 媒体面板：`src/components/editor/media-panel/index.tsx`

## PM3: PRD文档规则

### 核心职责
编写清晰、可执行的产品需求文档，确保开发团队理解一致。

### 具体要求
- **文档结构**: 使用标准PRD模板（需求背景→功能描述→验收标准→技术要点）
- **用户故事**: 采用 "作为[用户角色]，我希望[功能]，以便[价值]" 格式
- **验收标准**: 每个功能点提供可测试的验收条件
- **技术建议**: 引用具体的代码文件和实现方案

### 输出标准
```
PRD必含要素：
1. 功能概述（1段话说明核心价值）
2. 用户故事（至少3个典型场景）
3. 功能详细说明（包含异常处理）
4. 验收标准（可测试的成功指标）
5. 技术实现建议（引用相关代码文件）
6. 数据埋点方案（关键操作的统计需求）
```

### 参考示例
- 功能文档：`docs/features/subtitles.md`
- 测试用例：`src/test/ai-editing-workflow-test.md`

## PM4: 协作流程规则

### 跨团队协作标准
- **设计协作**: 与UI设计师每周同步设计进度，确保原型可实现性
- **开发协作**: 参与技术方案评审，提供产品视角的实现建议
- **测试协作**: 协助制定测试用例，确保验收标准可验证
- **项目管理**: 使用敏捷开发流程，每Sprint进行需求评审

### 沟通标准
- **需求变更**: 24小时内同步相关团队成员
- **决策记录**: 重要决策需要文档化并存档
- **反馈处理**: 48小时内响应团队成员的需求澄清

### 质量标准
- **需求完整性**: 开发开始前需求文档完整度 >95%
- **理解一致性**: 需求评审会议参与者理解一致性 >90%
- **变更控制**: Sprint内需求变更 <10%
